# 1536-wide NNUE experiment

Build feature `nnue1536` selects (768->1536)x2->16->32->1, ml inputs,
8 material output buckets. Default builds remain 1024. Both AVX2 and NEON
use the existing width-constant kernels; no runtime dispatch is added.
The 1536 build has no embedded net: set UCI EvalFile before searching.
Loader accepts exactly the raw payload or its 64-byte padded size, rejecting
wrong-width nets. Raw sizes: 1024 = 2118176; 1536 = 3167776 bytes.

Build (BelowNormal PowerShell, only when lab control is not pause):

```powershell
[System.Diagnostics.Process]::GetCurrentProcess().PriorityClass = 'BelowNormal'
cargo build --offline --release -p pawnstorm -j 6
cargo build --offline --release -p pawnstorm --features nnue1536 -j 6
cargo test --offline --release -p pawnstorm --features nnue1536 -j 6 --lib nnue::tests -- --test-threads=1
```

Release executables are installed as testing/engines/pawnstorm-w1536.exe
(1536) and pawnstorm-w1536-1024.exe (1024). Load a net with UCI EvalFile,
or run `pawnstorm-w1536.exe bench 18 <1536-net>` (single thread, 16 MB hash).
See the companion w1536-train branch's trainer/W1536.md for export smoke
and the training command. No trained 1536 net or playing-strength claim yet.

Verification on this PC: native CPU release profile, offline, BelowNormal.
The existing incremental-vs-refresh test passed at both widths. A CPU-only
Bullet quantisation smoke zero-extended a known 1024 network, preserving
both pairwise halves and small-layer weights. It produced 3167776 bytes;
bench signatures before / after / 1536 were identical:
- depth 10 baseline (embedded-net hand-eval fallback): 146622 nodes;
- depth 16 with explicit pawnstorm-2.1.nnue: 2306528 nodes;
- depth 18 with explicit pawnstorm-2.1.nnue: 4984504 nodes.

The checked-in default.bin is 1593408 bytes (incompatible with this branch's
1024 width); use an explicit 1024 net for meaningful baseline measurements.
ARM compile/runtime parity was not tested: remote access was prohibited.
No GPU work, downloads, remote operations or live-job changes were performed.

Final 1024 depth-18 NPS: 1802062, 1797513, 1804671 (median 1802062),
versus original 1793632-1808600 (median about 1797513): within 0.3%.
The loader/CLI additions are compiled only for nnue1536 to preserve the
1024 generated code path; initial unconditional CLI/loader additions showed
a repeatable ~2% code-layout cost and were removed from the default build.

1536 speed is strongly depth-dependent on this PC: initial five depth-16
samples 1422027-1489043 NPS (median 1471000, about 19% slower than 1024),
but repeated depth-18 samples about 0.83-0.95M NPS (roughly 47-54% slower).
The search signatures are identical, ruling out different search trees.
The reason for the depth dependence is unproven; do not extrapolate short
bench throughput to games. Timings are on a PC with existing lab jobs;
final baseline comparisons ran without our builds/tests in parallel.

Assuming 50-100 Elo per doubling of search speed, a 19% speed loss costs
roughly 15-30 Elo; a 47-54% loss costs roughly 45-110 Elo. These are heuristic
speed-only estimates, not measured Elo. A trained 1536 net must recover that
cost through better evaluation; fixed-node and fixed-time matches are needed.
Final release library suite: 7/7 passed for each width (14 total).
Companion trainer release CPU tests: 3 passed, 1 ignored throughput benchmark.
The supplied big7-list.txt was absent; future training requires that manifest.
